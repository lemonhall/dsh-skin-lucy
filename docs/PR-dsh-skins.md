# Submitting lucy-nightsignal to the Creative Workshop

The Workshop (dsh-market.com) is fed from the **dsh-skins** satellite repository.
`dsh-web` explicitly rejects content PRs and redirects them here, so this is the
one correct target:

| item | value |
| --- | --- |
| repository | `https://github.com/zhu1090093659/dsh-skins` |
| base branch | `main` |
| where the skin goes | `skins/lucy-nightsignal/` (a pure asset directory - no `package.json` inside it) |
| branch name used below | `feat/skins-lucy-nightsignal` |

The skin directory in this repository is already laid out exactly as dsh-skins
expects, so the contribution is a straight copy.

## 1. Fork and clone

```sh
# fork zhu1090093659/dsh-skins in the GitHub UI first, then
git clone https://github.com/<you>/dsh-skins.git
cd dsh-skins
git checkout main && git pull
git checkout -b feat/skins-lucy-nightsignal
```

## 2. Add the skin

```sh
cp -r /path/to/dsh-skin-lucy/skins/lucy-nightsignal skins/
```

Files that must come along: `skin.json`, `skin.css`, `patches.css`,
`assets/` (4 webp), `preview/light.jpg`, `preview/dark.jpg`, `README.md`,
`README.zh.md`. `assets-report.json` is an artefact of this project's asset
build and is not needed - drop it if the maintainers prefer a minimal directory.

## 3. Run the repository gates

```sh
pnpm install
node scripts/dsh-skin.cjs validate skins/lucy-nightsignal   # manifest v2 contract
pnpm skin-center:check                                      # catalog + CSS safety pipeline
pnpm skin-hooks:check                                       # reviewed hook identities
pnpm test
pnpm typecheck
pnpm build
```

Two notes that decide whether CI passes:

- `lib/index.js` and `src/reviewed-hooks.generated.ts` are generated by
  `scripts/skin-hooks-registry.mjs` and the AGENTS.md requires them to be
  regenerated whenever a `skin.json` changes. Run `pnpm skin-hooks:write`
  (or `pnpm build`) and **commit whatever it rewrites**, together with the skin.
- The default branch may have moved since this repository was prepared. Rebase on
  the latest `main` and re-run the gates before opening the PR; the PR template
  asks for evidence of exactly that.

## 4. Commit

```sh
git add skins/lucy-nightsignal src/reviewed-hooks.generated.ts lib
git commit -m "feat(skins): add lucy-nightsignal"
git push -u origin feat/skins-lucy-nightsignal
```

Conventional Commits, no emoji anywhere (code, comments, docs, commit messages).
